# FluNET 1.0 source-candidate verification gate

**Source roadmap status:** Batches 52–83 have source implementations. **Release status:** NOT VERIFIED / NOT RELEASED.

`ReleaseCandidateVerifier.Verify1_0` checks side-effect-free structural invariants (unique frame/type contracts, extension-contract uniqueness, topology validity and separator contract). It does **not** replace compiler/test execution.

Public `StandardLanguageIdentity.Version` intentionally remains `0.3` until every required build/test command succeeds against the exact final tree.

## Required verification

```bash
dotnet restore FluNET.sln
dotnet build FluNET.sln --configuration Release --no-restore
dotnet test FluNET.sln --configuration Release --no-build

# The complete 1.0 candidate CLI is additive and is not yet in the historical solution file.
dotnet build src/FluNET.Tool/FluNET.Tool.csproj --configuration Release
```

Then run contract/tool smoke checks, for example:

```bash
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj -- version
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj -- contract
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj -- --help
```

## Promotion only after a green gate

After successful evidence exists for the exact tree:

1. fix any failures without changing contract intent;
2. regenerate/persist final contract snapshots;
3. set `StandardLanguageIdentity.Version` to `1.0` in an isolated promotion commit;
4. update release-facing docs from candidate to released;
5. run the verification gate again on the promotion commit;
6. only then create a release/tag if explicitly requested.

No empty GitHub status list and no source-level implementation ledger is equivalent to a passing build/test run.
