# FluNET 1.0 production-readiness verification gate

**Status: SOURCE GATE PREPARED — NOT VERIFIED / NOT RELEASED.**

`FluNET.Tool` is part of `FluNET.sln`, targets `net9.0`, and is packaged as the `FluNET.Tool` .NET tool preview. `ReleaseCandidateVerifier.Verify1_0` and `ReleasePromotionGate` are side-effect-free structural/evidence policies; neither replaces compiler/test execution.

Public `StandardLanguageIdentity.Version` intentionally remains `0.3` and Tool package metadata remains `0.3.0-preview` until exact-tree verification succeeds.

## Canonical gate

Bash:

```bash
./scripts/verify-release.sh
```

PowerShell:

```powershell
./scripts/verify-release.ps1
```

The scripts execute the equivalent of:

```bash
dotnet restore FluNET.sln
dotnet build FluNET.sln --configuration Release --no-restore
dotnet test FluNET.sln --configuration Release --no-build

dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- version
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- contract
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- --help

dotnet pack src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build
# followed by a local dotnet tool install + help smoke against the produced package
```

## CI integration

`.github/workflows/ci.yml` runs the same canonical gate on `ubuntu-latest`, `windows-latest`, and `macos-latest` using .NET `9.0.x`.

Current GitHub execution is blocked before checkout by an account billing lock. This is an infrastructure/account condition, not evidence about FluNET compilation or tests. The gate remains unverified until at least one actual runner executes the steps to completion.

## Promotion rule

1. Run the complete gate on the current unpromoted candidate.
2. Fix every compiler/test/package/smoke failure and rerun the complete gate.
3. Only after all evidence is green, make an isolated public version/package promotion.
4. Run the complete gate again on that promoted exact tree.
5. Only then may an explicitly requested release/tag be created.

Static review, source tests that have not run, a runner failure before checkout, an empty status list, or a contract manifest are not passing evidence.
