# FluNET 1.0 production-readiness verification gate

**Status: SOURCE GATE PREPARED — NOT VERIFIED / NOT RELEASED.**

`FluNET.Tool` is now part of `FluNET.sln`, so the ordinary solution Release build covers the candidate CLI as well as the engine, compatibility CLI and tests.

`ReleaseCandidateVerifier.Verify1_0` checks side-effect-free structural invariants. It does **not** replace compiler/test execution. Public `StandardLanguageIdentity.Version` intentionally remains `0.3` until the exact candidate tree is green.

## Canonical gate

Bash:

```bash
./scripts/verify-release.sh
```

PowerShell:

```powershell
./scripts/verify-release.ps1
```

The scripts execute:

```bash
dotnet restore FluNET.sln
dotnet build FluNET.sln --configuration Release --no-restore
dotnet test FluNET.sln --configuration Release --no-build

dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- version
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- contract
dotnet run --project src/FluNET.Tool/FluNET.Tool.csproj --configuration Release --no-build -- --help
```

## Promotion rule

A source implementation, empty GitHub status list, successful static review or contract manifest is not equivalent to a passing Release gate. Any compiler/test failure becomes a stabilization change and the complete gate must be rerun on the resulting exact commit.

Only after a green gate should the public language identity be promoted in an isolated commit and the full gate run again. Release/tag creation remains a separate explicit action.
