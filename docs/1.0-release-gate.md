# FluNET 1.0 release gate

**Status: GATE IMPLEMENTED — RELEASE BLOCKED / NO VERIFICATION EVIDENCE.**

Batch 89 deliberately does not equate source completion with release completion.

At the RC gate check performed before this ledger was written:

- the execution environment had no `dotnet` executable, so restore/build/test/package commands could not be run locally;
- GitHub returned zero combined status checks for the RC head;
- GitHub returned zero workflow runs for the RC head;
- no workflow was manually triggered or rerun.

Therefore there is currently **no valid evidence** for `Restore`, `ReleaseBuild`, `ReleaseTests`, tool packing or tool installation smoke checks. Public `StandardLanguageIdentity.Version` remains `0.3`; `FluNET.Tool` package metadata remains `0.3.0-preview`.

## Gate policy

`ReleasePromotionGate` models the evidence requirement without executing external commands. Required checks are:

1. restore;
2. Release solution build;
3. Release tests;
4. static contract checks;
5. direct Tool smoke;
6. Tool pack;
7. local Tool install smoke.

With complete green evidence while the public language identity is still `0.3`, the gate permits only an isolated **version-promotion commit**. It does not permit a release yet. The complete gate must then be rerun on the promoted exact tree; only complete evidence with the public identity aligned to `1.0` permits release/tagging.

## Canonical executable gate

```bash
./scripts/verify-release.sh
```

or:

```powershell
./scripts/verify-release.ps1
```

These scripts are the source of external build/test/package evidence. A future CI job may invoke them, but Batch 89 does not create or trigger a workflow merely to manufacture a green status.

## Current decision

**Do not bump `StandardLanguageIdentity.Version`, do not change the Tool package to `1.0.0`, and do not create a 1.0 tag/release yet.**

The implementation scope is complete; the remaining blocker is real verification evidence plus any stabilization fixes revealed by that evidence.
