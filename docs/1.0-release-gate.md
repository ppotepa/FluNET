## Gate policy

`ReleasePromotionGate` models the evidence requirement without executing external commands. Required checks are:

1. restore;
2. Release solution build;
3. Release tests;
4. static contract checks;
5. direct Tool smoke;
6. Tool pack;
7. local Tool install smoke.

With complete green evidence while the public language identity is still `0.3`, the gate permits only an isolated **version-promotion commit**. It does not permit a release yet. The complete gate must then be rerun on the promoted exact tree; only complete evidence with the public identity aligned to `1.0` permits release/tagging.

## Canonical executable gate

```bash
./scripts/verify-release.sh
```

or:

```powershell
./scripts/verify-release.ps1
```

GitHub CI invokes these same scripts. A runner/infrastructure failure before checkout is not compiler/test evidence and must not be interpreted as a failed or successful FluNET build.
