## Production-readiness work now present

### Verification and packaging

- `FluNET.Tool` is included in `FluNET.sln` and targets `net9.0` like the engine/tests.
- `scripts/verify-release.sh` and `scripts/verify-release.ps1` are the canonical Release gates.
- `.github/workflows/ci.yml` installs .NET 9 and invokes those same scripts on Linux/macOS/Windows.
- the gate builds/tests the solution and smoke-checks the locally packed/installed `FluNET.Tool` package;
- the historical `FluNET.Cli` remains compatibility-only and is not packable.

The current GitHub Actions environment is blocked before checkout by an account billing lock. That does not change source readiness and does not provide build/test evidence.

### Reconciliation durability and concurrency

- stable `SyncDefinition.Id`;
- persisted last-converged baseline with in-memory and checksummed durable stores;
- `FAIL`, `KEEP TARGET`, and `KEEP SOURCE` conflict policies;
- priority-based `IReconciliationMutator` registry; mutators produce ordinary execution plans rather than executing effects directly;
- per-target leases with heartbeat and monotonic fencing tokens;
- optional shared-filesystem durable lease store;
- AsyncLocal fencing context available to custom mutation providers;
- checksummed phase checkpoint journal;
- interrupted nonterminal runs recover by re-observing state rather than blindly resuming an unknown mutation phase;
- physical file writes use sibling temp + write-through/fsync + replace.

### Security

`AddSecureFluNetHost(...)` is an opt-in production host profile:

- symlink-aware configured-root containment;
- HTTPS-only by default;
- explicit host allow-list;
- private/loopback literal and DNS-result protection by default;
- redirects disabled in the underlying handler and validated on every hop;
- authenticated cross-origin redirects are rejected;
- mutation redirects are rejected rather than silently replayed.

Compatibility defaults remain unchanged for existing hosts.

### Observability

`IFluNetTelemetrySink` receives metadata-only events. Built-in command telemetry includes frame/effect/concurrency/outcome/duration/cache/idempotency metadata; reconciliation telemetry includes definition id, resource kinds, conflict policy, diff counts, mutator id and fencing token. Raw arguments, resource paths, JSON records and secret values are intentionally omitted.
